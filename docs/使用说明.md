## 零、登录界面也能降级验证（最重要）

很多人以为只有 Cloud Shell / Antigravity 那种「授权页弹出的二维码」才能降级。**不是的：普通 Google 账号登录界面一样能降级。**

### 场景

在 `https://accounts.google.com` 输入账号密码点「下一步」，如果这个账号被 Google 要求「验证身份」，页面会**直接跳到扫码页**（`/v3/signin/challenge/iap/qrcode`），根本不给你选短信的机会。这一步以前只能拿另一台手机扫码。

### 操作（和二维码页完全一样的四步）

1. 等页面上的二维码图案**完全渲染**出来（黑色方块画完，别在转圈时就点）
2. 点右下角 **⚡ 圆点** 展开面板
3. 点 **「⚡ 手动降级到短信页」**
4. 跳到 `/challenge/iap?idv_xdevice=1` 后，面板里填接码号 → **「填入号码并点下一步」** → 收到 `G-xxxxxx` 六位码 → 手动填入 → 登录继续

### 为什么登录页也能成

登录流程和 Cloud Shell 流程用的是**同一个** `iap/qrcode` 挑战页、同一套
`MypxBd` → `consent` → `YDtwf` → `[3,null,4]` 回落链路。
扩展判断「当前在哪一步」用的是 `location.pathname`（2.14.1 修的正是这里），
**跟你从哪个入口进来无关**。UA 规则也只覆盖验证链路本身，所以登录页同样命中。

> 反过来说：如果哪天登录页突然降级失败，先看 2.14.1 那条——只要 `pageStep` 还能正确识别
> `/v3/signin/challenge/iap/qrcode`，登录入口和 Cloud Shell 入口的行为就是一致的。

### 三个前提（缺一个就不动）

| 前提 | 检查方法 |
|---|---|
| 当前 URL 是 `/v3/signin/challenge/iap/qrcode` | 面板地址行会显示；不是这个路径面板不注入 |
| 二维码已渲染完 | 肉眼确认图案出现；否则 `BarcodeDetector` 识别不到，回落 jsQR 也没图可解 |
| 浏览器 Chrome / Edge 88+ | 低版本没有 `BarcodeDetector`，需先跑 `scripts/fetch-jsqr.ps1` 拉 jsQR |

### 一个必须记住的边界

**不要**从第三方应用的 OAuth 二维码页（Antigravity、Gemini Code Assist 等）直接降级：
那里的 `continue` 参数带多层嵌套重定向，降级后会被 Google 打回二维码。
这种情况按 [附录 A](#附录-a原作者使用教程havenicec-v110-原版) 从 Cloud Shell 走一遍，账号全局解锁后再回第三方应用登录。

**登录界面不属于这个例外**——登录页的 `continue` 指向的是账号自身流程，是干净的，可以直接降。

### 顺带一句 2.8 的教训

别为了让登录页也生效就把 DNR 的 UA 规则铺满 `accounts.google.com/*`：
那样登录页会被判「此浏览器或应用可能不安全」直接跳 `/v3/signin/rejected`。
规则只覆盖验证链路（现在这 3 条），登录页反而正常。

## 一、安装

### 1. 加载已解压的扩展

1. 地址栏输入 `edge://extensions/`（Chrome 则是 `chrome://extensions/`）
2. 右下角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本仓库根目录
4. 确认扩展列表里出现「Google QR 自动降级短信助手」，版本 `2.20.0`

| 权限 | 用途 |
|---|---|
| `declarativeNetRequest` | 只在验证链路把 User-Agent 改成 iPad Mini / iPhone |
| `webNavigation` | 导航完成后补注入 content script（SPA 路由不会重新触发） |
| `debugger` | 调试桥（仅本地）；以及 reCAPTCHA 点击 |

| `scripting` / `tabs` | 在指定标签页执行脚本、列标签 |

## 二、正常使用流程

```
Google 二维码验证页（登录界面 / Cloud Shell 都算）
        ↓  点右下角 ⚡ → 「⚡ 手动降级到短信页」
后台发 MypxBd → consent → YDtwf，命中 [3,null,4]
        ↓  自动跳转
/challenge/iap?idv_xdevice=1（短信方式选择页）
        ↓  面板里填接码号 → 「填入号码并点下一步」
Google 下发 6 位码
        ↓  手动填入
验证完成
```

### 面板说明

- 默认是右下角 42×42 的 **⚡ 圆点**，点开才是面板（避免遮挡 Google 的「下一步」）
- `×` 是**收起**，不是关闭
- 面板里的状态区会实时显示：页面令牌 tl/dsh/at 是否存在、RPC 每一步的 HTTP 状态、号码校验结果
- 短信页多两个控件：号码输入框 + 「填入号码并点下一步」

### 失败时的按钮变化

| 面板显示 | 含义 | 下一步 |
|---|---|---|
| `❌ 服务端没返回 [3,null,4]` | RPC 没拿到回落标记 | 按 F5 拿新二维码再试 |
| `二维码会话已失效` | 这张码已被消耗或超时 | F5 刷新 |
| `❌ Google 拒绝了这次提交：出了点问题…` | Google 服务端风控 | 换号 / 换账号 / 换 IP |

## 三、报错对照表（实测）

### 「出了点问题 · 抱歉，出了点问题。请重试。」

这句话是 Google 的**兜底风控文案**，本身不带信息。实测下来的归因：

| 触发条件 | 验证方式 |
|---|---|
| 号码被叠成 18 位 | 看输入框实际值，`+57 000000000000000000` 这种 |
| 国家与号码不匹配 | 看 `div[role=combobox]` 文本是否是号码对应的国家 |
| 号码被判定为虚拟号 / 接码号 | 换一个国家或号段，看报错是否变化 |
| 账号已被停用 | 页面会跳到 `/v3/signin/speedbump/disabled/additionalinformation`，标题是「请说明我们为何应恢复您的账号」 |
| 出口 IP 是机房 IP | 换到非云 ISP 节点后，同样的提交会变成「此号码用于验证的次数过多」 |

**关键判据**：换 IP 后报错文案从「出了点问题」变成「此号码用于验证的次数过多」，
说明 IP 侧已经不再是瓶颈，剩下的问题在号码本身。

### 「此号码用于验证的次数过多。请换个电话号码。」

号码维度的配额用完了。换号。

### 「请说明我们为何应恢复您的账号」

账号被停用，进入申诉流程（3 步）。这与扩展无关。

### reCAPTCHA

- 机房 IP 下几乎必出图片题，**图片题无法用脚本通过**（Google 按行为指纹判分）
- 换成非云 ISP 的节点后，往往点一下勾选框就直接通过
- 勾选框坐标 = anchor iframe 的 rect + (26, 26)
- 必须发完整三段鼠标事件：`mouseMoved` → `mousePressed(buttons:1)` → 等 200ms → `mouseReleased(buttons:0)`；只发 pressed/released 无效

## 四、填号逻辑（v2.20 为什么这么写）

```js
// 1. 统一成完整国际号
const digits = raw.replace(/[^\d]/g, "");
const full = "+" + digits;

// 2. 先清空，等受控输入把「+国家码」回填完
field.focus();
setNative(field, "");
await new Promise(r => setTimeout(r, 180));

// 3. 一次性插完整国际号（不要拆成「切国家 + 只填本地号」）
document.execCommand("insertText", false, full);

// 4. 自校验长度，不对就停止，绝不提交
const got = field.value.replace(/[^\d]/g, "");
if (got !== digits) return;
```

### 为什么不能手动切国家

短信页的国家选择器是 `div[role="combobox"]`，**不是原生 `<select>`**。
早期版本用 `document.querySelectorAll("select")` 去找，永远找不到，
于是「切不动国家却仍然提交」，Google 按默认区号解析必然失败。

正确做法：直接给 `input#phoneNumberId`（`jsname="YPqjbf"`）插完整的 `+国际号`，
Google 自己会把 combobox 切过去。

## 五、调试桥（可选）

只在本地 `127.0.0.1:8799` 上工作，不装接收端时所有请求静默失败。

### 命令集

| 命令 | 参数 | 说明 |
|---|---|---|
| `eval` | `tab`, `code` | 在页面执行函数体（**必须以 `return` 结尾**，外层包了 `(async function(){...})()`） |
| `click` | `tab`, `x`, `y` | CDP 三段式点击，坐标是 CSS 像素 |
| `insert` | `tab`, `text`, `clear?`, `focus?` | `clear` 用真实 Ctrl+A + Backspace |
| `key` | `tab`, `key`, `vk?` | 默认 `Enter` |
| `focus` | `tab`, `selector` | `DOM.focus`，密码框必须用这个 |
| `cdp` | `tab`, `method`, `params` | 透传任意 CDP 命令 |
| `shot` | `tab`, `name` | 截图 → POST 到本地 sink |
| `nav` | `tab`, `url` | 导航 |
| `tabs` / `ver` / `reload` / `detach` | — | 列标签 / 查版本 / 重载扩展 / 断开调试 |

### 已验证的页面细节

| 元素 | 选择器 | 备注 |
|---|---|---|
| 电话号码框 | `input#phoneNumberId`，`jsname="YPqjbf"` | 受控输入，会自己补 `+国家码` |
| 国家选择器 | `div[role="combobox"]` | **不是 `<select>`**；选项是隐藏的 `<span>` |
| loading 遮罩 | `div.ZQxJQe`，`jsname="OQ2Y6"` | 全屏 `position:fixed; z-index:5; pointer-events:auto`，会吞掉所有点击 |
| 提交按钮 | `button` 且 text 为 `下一步` / `Next` | 必须过滤 `getBoundingClientRect().width > 0`，否则会点到面板里的按钮 |

### 常见坑

1. **CDP 坐标是 CSS 像素**，不要乘 DPR
2. 点击 Google 的账号行要用 `element.click()`，CDP 鼠标事件对它无效
3. 密码框：`input[type=password].focus()` 无效（`activeElement` 是 `IFRAME`），必须 `DOM.focus` + `Input.insertText`，提交用 `Enter` 而不是点「下一步」
4. 扩展被回收后桥会断：`chrome.alarms` 每分钟会唤醒一次，等一分钟或手动 `reload`

## 六、FAQ

**Q：面板不出现？**
A：确认地址是 `accounts.google.com` 下的 `/challenge/iap*`；扩展的 `webNavigation` 会在导航后补注入。仍不出现就刷新页面。

**Q：点了降级没反应？**
A：看面板状态区的令牌行。`tl` / `dsh` 都打了 ✓ 才会发 RPC；都是 ✗ 就用「手动粘贴二维码链接」把 `g.co/verify/...` 粘进去。

**Q：能自动填 6 位验证码吗？**
A：不能。码在短信里，需要你自己取。接码平台需要单独登录。

**Q：为什么号码明明对了还报错？**
A：见第三节。IP 信誉、号码段历史、账号风控三者叠加，代码侧能做的只有「格式正确 + 不叠串 + 提前校验」。

**Q：登录界面也能用吗？**
A：能，见第零节。前提是当前页是 `/v3/signin/challenge/iap/qrcode`，且不是第三方 OAuth 的跳转链。

## 附录 A：原作者使用教程（havenicec v1.1.0 原版）

> 以下整理自 [havenicec/google-qr-sms-helper](https://github.com/havenicec/google-qr-sms-helper)（MIT）的 README。
> 上游 v1.1.0 是「全自动」按钮（**⚡ 一键降级到短信选择框**）；本 fork 从 2.19 起默认改成手动（**⚡ 手动降级到短信页**），流程一致，只是不再自动点。

### A.1 安装（原作者的两种方式）

**方式 1：下载 Release 压缩包（推荐新手）**
1. 到 Releases 页下载 `google-qr-sms-helper-v1.1.0.zip`，解压到本地文件夹
2. 浏览器地址栏输入 `chrome://extensions/` 回车
3. 打开右上角 **开发者模式 (Developer mode)**
4. 点 **加载已解压的扩展程序 (Load unpacked)**，选中解压出来的文件夹

**方式 2：Git 克隆安装**
```bash
git clone https://github.com/havenicec/google-qr-sms-helper.git
```
然后在 `chrome://extensions/` 开「开发者模式」→「加载已解压的扩展程序」→ 选 `google-qr-sms-helper` 目录。

> 装本 fork 就直接选本仓库根目录，不要再去 clone 上游。

### A.2 核心前提（原作者原话）

> **不要**直接从第三方客户端（如 Antigravity / Gemini Code Assist 授权页）弹出的二维码页面降级（其 `continue` 参数包含多层嵌套重定向，会被 Google 重新拦截回二维码）。
> **必须先打开 Google Cloud Console，通过 Cloud Shell 唤出原生的 `Verify` 窗口**。在这里过完一次短信验证后，账号权限全局解锁，再回 Antigravity 等工具登录就能直接通过。

（补充：这条只针对第三方授权页；**普通登录界面的二维码不在此列**，可以直接降，见第零节。）

### A.3 第 1 步：打开 Cloud Console 唤起 Cloud Shell 验证

1. 浏览器登录要验证的 Google 账号，访问 <https://console.cloud.google.com/>
2. 点右上角导航栏的 **「激活 Cloud Shell」终端图标 `[>_]`**
3. 底部弹出 `Verify your account` 窗口，点蓝色 **`Verify`** 按钮

### A.4 第 2 步：在二维码页面点降级

1. 点 `Verify` 后会弹出二维码验证页（`/v3/signin/challenge/iap/qrcode`）
2. 等二维码图案加载出来，点右下角面板的降级按钮：
   - 上游：`BarcodeDetector` 识别二维码 → 自动发 `MypxBd` 与 `YDtwf ([null, uuid, dsh, 7, null, tl, false])` → 拿到 `[3, null, 4]` → 伪装 iPad Mini → 跳 `uplevelingstep/selection?...&idv_xdevice=1`
   - 本 fork：同样识别与发 RPC，只是要你自己点（2.19 起默认不自动）

### A.5 第 3 步：选「短信」并接码

1. 跳到验证方式选择页，勾 **Text message (SMS) / 短信**（或语音通话）→ 下一步
2. 填接码手机号（任意国家/地区的接码号或实体卡都行）→ 发送验证码
3. 收到 `G-xxxxxx` 六位码填入 → **Next**，完成验证
4. 回 Cloud Shell / Antigravity / Gemini CLI 刷新即可正常用

### A.6 原作者 FAQ 三问

**Q1：从别的链接点进二维码页，点降级又跳回二维码？**
只有从 `console.cloud.google.com` 点右上角 Cloud Shell `[>_]` → `Verify` 唤出的二维码页，`continue` 才是纯净的 `https://accounts.google.com/uplevelingstep/selection?TL=...&authuser=0&flowName=GlifWebSignIn&sarp=1&scc=1`。

**Q2：为什么默认伪装成 `iPad Mini`，不是 `iPad Pro` 或桌面？**
Google 的 `uplevelingstep/selection` 会校验 UA：桌面端（Windows / macOS）与 Chrome F12 里的 `iPad Pro 13` 发的都是 `Macintosh; Intel Mac OS X` 桌面 UA，会被无视 `idv_xdevice=1` 强行打回二维码；`iPad Mini` 发的是纯移动 UA（`iPad; CPU OS 16_6 like Mac OS X ... Mobile/15E148`），而且提交六位码的 `/_/IdvUplevelingUi/data/batchexecute` 必须前后 UA 完全一致（上游 v1.1.0 已用 `declarativeNetRequest` 全路径覆盖；本 fork 2.8 起收窄到验证链路 3 条规则）。

**Q3：点降级提示「未能在当前页面识别到二维码」？**
确认浏览器是 Chrome / Edge 88+（支持原生 `BarcodeDetector`），并等二维码图案完全显示后再点。本 fork 在 `BarcodeDetector` 不可用时会回落 jsQR（需先跑 `scripts/fetch-jsqr.ps1`）。
